# 인덕 ERP 월별 자료 수집기

인덕회계법인 ERP(IBCENTER, `http://induk.ibcenter.kr`)에서 **월 4종 세트**를 자동으로 받아 오는 스크립트입니다.
지금은 개발·검증용이지만, 나중에 jaytax 안에서 버튼 하나로 돌리기 위한 **원형(prototype)** 이기도 합니다.

## 지금 누가 쓰나

| | 지금 | 나중 |
|---|---|---|
| 김민섭 담당자 | ERP에서 손으로 엑셀 내려받아 **jaytax 대사 화면에 끌어다 놓기** | 그대로 두거나, 아래 자동화가 서면 생략 |
| 개발·검증 | 이 스크립트로 원본을 받아 대사 | 그대로 |

**담당자 업무에는 이 스크립트가 등장하지 않습니다.** 터미널을 쓰게 하지 않으려고 그렇게 설계했습니다.

## 실행

```bash
# 기장24팀 (정남지 계정) — 전월분
node scripts/erp/fetch.mjs --month 2026-08

# 감사팀 (정우철 계정)
node scripts/erp/fetch.mjs --profile audit --bu 0205 --dept 감사팀 --month 2026-08

# 두 팀을 한 번에 (Windows)
scripts\erp\month.cmd 2026-08
```

크롬이 뜨면 **사람이 직접 로그인**합니다. 비밀번호는 스크립트가 다루지 않습니다.
세션은 계정별 크롬 프로필에 남아 다음 달에는 로그인이 생략됩니다.

| 옵션 | 뜻 |
|---|---|
| `--month 2026-08` | 대상 월(기본: 전월) |
| `--profile tax\|audit` | 계정별 크롬 프로필. tax=정남지, audit=정우철 |
| `--bu 1024\|0205` | 부서코드. 기장24팀=1024, 2본부5팀(감사)=0205 |
| `--dept 기장24팀` | 파일 이름에 쓸 팀 이름 |
| `--out "경로"` | 저장 폴더 지정 |
| `--only slip,ledger` | 일부만 받기 |
| `--depts` | 그 계정이 볼 수 있는 부서·코드 확인 |
| `--inspect <리포트>` | 조회 조건 배우기(사람이 한 번 조회하면 폼 값을 찍어 준다) |
| `--doctor` | 크롬·폴더 점검(크롬 안 띄움) |

기본 저장 폴더는 프로필로 갈립니다 — tax는 `5520_기장사업부관리/기장24팀ERP데이터`, audit은 `4.영업관리/2본부5팀`.

## 받는 4종

| 파일 | ERP 화면 | 쓰임 |
|---|---|---|
| `_거래전표.xls` | 거래전표 리스트 | **발행 대사**(사업자등록증·공급가액·내역·계약유형) |
| `_원장.xls` | 부서별원장 | 정본. 발행(차변)·입금(대변)·잔액. 거래처코드·**사원명(담당자)** 도 여기 |
| `_미수금대장.xls` | 기간 미수금대장 | 건별 잔액(invoiceNo·계약번호) |
| `_미수금현황.xls` | 기준일자 미수금현황 | 계정 5줄 요약(통제합계) |

`--only clients` 로 전사 거래처 마스터(7만 건·90MB)도 받을 수 있습니다. 매달 받을 것은 아니고
**새 거래처의 ERP 코드·대표자·주소가 필요할 때만** 받습니다.

### 다시 밟지 말아야 할 함정 넷

1. **[검색]이 질의이고 [조회]는 상세 진입이다.** 목록 화면의 질의는 `search('search')`,
   `doSubmit()` 은 고른 행의 상세로 넘어간다. doSubmit 을 질의로 부르면 rowcount 0 →
   "레코드가 없습니다"만 뜬다.
2. **엑셀을 한 번 받으면 그 크롬이 새 탭을 못 연다**(`Target.createTarget` 실패).
   그래서 리포트마다 탭을 새로 열지 않고 **탭 하나를 계속 이동**시킨다.
3. **화면 로딩이 30초를 넘는다.** `waitUntil:'commit'` + 180초로 두고,
   `myform`·`xls_click` 이 준비됐는지로 완료를 판단한다.
4. **엑셀 열 순서는 고정이 아니다.** 위치가 아니라 **열 이름**으로 찾을 것.

## 자동화로 가는 길 — 무엇이 걸리는가

지금은 브라우저를 띄워 사람이 로그인합니다. 웹에서 버튼 하나로 돌리려면 두 가지가 걸립니다.

**① 실행 환경** — 브라우저 자동화(Playwright)는 **브라우저가 설치된 서버**가 필요합니다.
Vercel 같은 서버리스에서는 못 돕니다. 실무적인 선택지:

| 방법 | 설명 | 난이도 |
|---|---|---|
| **(A) 사무실 PC 예약 실행** | Windows 작업 스케줄러가 매월 25일에 `month.cmd` 실행 → 받은 파일을 jaytax에 자동 업로드 | 낮음. **지금 바로 가능** |
| (B) 상시 서버 | 사내 PC나 소형 서버에 Node+크롬을 두고 jaytax에서 호출 | 중간. 서버 관리 필요 |
| (C) ERP 벤더 API | IBCENTER에 자동 내보내기/API 요청 | 벤더 협의. 가장 깔끔 |

**② 로그인** — 지금은 사람이 칩니다. 무인으로 돌리려면 **비밀번호를 어딘가 저장**해야 하는데,
"비밀번호는 다루지 않는다"는 원칙과 정면으로 부딪칩니다. 다만 **크롬 프로필에 세션이 남아**
있어서, 세션이 살아 있는 동안은 로그인 없이 돕니다. (A)를 쓰면 사람이 한 번 로그인해 둔 PC에서
돌기 때문에 **비밀번호를 저장하지 않고도** 자동화가 됩니다 — 세션이 끊기면 그때만 한 번 더 로그인합니다.

> ERP는 비밀번호를 5회 틀리면 그 브라우저가 영구 잠금된다는 경고가 있습니다.
> 자동 로그인을 붙일 때 재시도 루프를 절대 넣지 말 것.

**권장 순서**: (A)로 시작 → 파일이 자동으로 쌓이면 jaytax가 폴더를 읽어 대사까지 자동 →
그래도 손이 가면 (C)를 벤더에 요청.
